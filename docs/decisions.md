- 2026-11-01 · fw-ips runs Ubuntu 24.04 LTS · long support window, SSM agent preinstalled on the official image, and first-class packages for the fw-ips stack
- 2026-11-01 · `<domain>` is a subdomain delegated to Route 53 by NS records at the parent's DNS provider; the real name stays out of the repo · the parent domain's email forwarding and other records stay untouched, and a lab mistake cannot affect them

- 2026-11-01 · Instance roles use `mailbridge-lab-ssm-min` instead of `AmazonSSMManagedInstanceCore` · the managed policy allows `ssm:GetParameter` on every parameter, and the `aws/ssm` key decrypts for anyone allowed to call SSM, so any host could read every secret
- 2026-11-01 · VPN users get dynamic addresses, and only the admin device has a `ccd` file with a fixed address · Marko chose this because proving who held an IP from the logs makes the attack scenarios more realistic
- 2026-11-01 · During the fw-ips hand build, stop the instance and release the Elastic IP between sessions, as a documented exception to removing paid resources · terminating would delete the hand-built config, and the disk costs far less than rebuilding each session
- 2026-11-01 · fw-ips forwarding rules match on addresses, and private subnets use `snat` to 10.0.1.10 · one interface carries both internet and VPC traffic, and scoping NAT to private subnets keeps real VPN client addresses visible
- 2026-11-01 · Suricata's NFQUEUE will use a separate later-priority chain in 1.11 · an accepted packet skips the rest of its chain, so queueing in the policy chain could bypass firewall rules
- 2026-11-01 · VPN clients may reach Unbound on 10.0.1.10, with a pushed /32 route added in 1.10 · `mail.<domain>` can't resolve otherwise, and users still reach only the proxy through the firewall
- 2026-11-01 · fw-ips answers ping from the admin pool only, and its `output` chain stays open · the session check keeps working without helping a stolen user cert map the host, and §4 defines no outbound policy for fw-ips
- 2026-11-01 · A new nftables input policy is load-tested from a separate file before replacing `/etc/nftables.conf` · an `input` drop can lock out the host, and a stop and start restores the last good rules
- 2026-11-01 · Unbound listens on 10.0.1.10 only, with a `static` local zone for `mail.<domain>` and query logging off · other names under the domain must still resolve, access stays limited by address, and §8 doesn't list DNS logs
- 2026-11-01 · The real domain reaches Ansible through an untracked vars file · the repo is public and the name isn't a secret, so an SSM read and IAM grant aren't justified
- 2026-11-01 · Private hosts keep AmazonProvidedDNS, recorded as a known gap for scenario 2.2 · a DHCP change would not stop direct queries to 10.0.0.2, and it would make fw-ips depend on its own Unbound
- 2026-11-01 · Unbound doesn't validate DNSSEC · AmazonProvidedDNS returns no signatures, so validation fails every forwarded name, and TLS still stops a forged address being trusted
- 2026-11-01 · Suricata covers network behaviour and TLS metadata; ModSecurity alone inspects web payloads · TLS ends at Nginx, past fw-ips, and decrypting on the internet-facing host would put private keys there
- 2026-11-01 · Suricata fails closed, with `queue` and no `bypass` · an attacker can't stop it to get unscanned access, and SSM and the VPN stay up for recovery
- 2026-11-01 · Suricata uses the Ubuntu package and ET Open in alert-only mode, with `eve.json` limited and rotated · no extra package source, broad detection without false positives cutting traffic, and a protected disk
